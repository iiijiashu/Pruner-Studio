# Pruner Studio implementation contract

This repository is the clean open-source rebuild. Never copy credentials, account identifiers, personal catalog exports, QR images, operation logs, or song lists from the parent directory.

## Product decisions

- **Product positioning**: Local-first single-user **4-destination daily NetEase Cloud Music desktop client, multi-channel high-res audio hub, and safe playlist pruner** (version `0.3.0`) with QR login, remembered session, and offline read-only library access when cached accounts exist.
- **Desktop shell, transparent floating lyrics, global hotkeys & local-only transport**:
  - Run a single-worker `Starlette + Uvicorn` server bound strictly to `127.0.0.1` under an OS data-directory lock; serve only explicit allowlisted files under `web/` (including `web/desktop_lyrics.html`) with `Cache-Control: no-store, must-revalidate` and `Pragma: no-cache`; never enable CORS; enforce exact loopback Host/Origin/Fetch-Metadata checks and JSON content types on mutations.
  - On Windows, default to a single `pywebview` Edge WebView2 window (isolated storage under the app data dir, custom `web/assets/icon.ico` via WinForms + Win32 `WM_SETICON`, single-instance relaunch window wake) with `pystray` system tray (`显示窗口`, `播放 / 暂停`, `桌面歌词`, `解锁桌面歌词`, exit), on-demand transparent frameless always-on-top resizable Desktop Floating Lyrics (`web/desktop_lyrics.html`, default `820×120` bottom-center, debounced 500ms `desktop_lyrics_bounds` persistence, single retry fallback if `transparent=True` fails, transparency-safe Win32 `WS_EX_TRANSPARENT | WS_EX_LAYERED` click-through lock), toggleable pure-`ctypes` Windows global hotkeys (`Ctrl+Alt+Right/Left/P/L/D` -> `next`/`prev`/`toggle_play`/`toggle_like`/`toggle_desktop_lyrics` over SSE `event: hotkey`), and automatic browser fallback; preserve `PRUNER_STUDIO_BROWSER=1`, `PRUNER_STUDIO_NO_GUI=1`, and `PRUNER_STUDIO_NO_BROWSER=1` overrides.
- **4-destination Chinese-first UI + dedicated search results view**:
  - Collapsible left navigation rail with four primary destinations: `发现`, `音乐库`, `歌单清理`, `设置与同步` (auto-collapsing into a slide-over drawer at narrow widths including `1024×768` at 125%/150% Windows DPI scaling), plus a dedicated `#view-search` full-page search view (not a rail button) opened from `Ctrl+K`.
  - `发现` pairs an equal-width 2-column listening hero (`真·心动电台` with a continuous `1%` `20%–80%` explore slider + `私人漫游`) with `本地听歌洞察`, a horizontal `沉睡宝藏` strip (up to 12 cards), and `每日推荐`.
  - `设置与同步` uses a 3-tab top switcher: `偏好设置` (including the top「外观」theme/appearance card), `多渠道与会员` (channel cards with raw credentials collapsed behind a closed-by-default `高级凭据` disclosure and primary `测试连通性` action), and `同步与备份`.
  - Persistent global bottom player across all views (explicit `词` desktop-lyrics toggle, inline current lyric `#player-inline-lyric`, `更多` overflow popover, unified playback queue, Martin Fiedler balanced dithered shuffle with `playHistoryStack`, safe same-origin Web Audio loudness normalization + 150ms crossfade, Media Session controls, global `Space` play/pause outside `歌单清理`/modals/inputs, `Ctrl+ArrowLeft/Right` prev/next, `Ctrl+ArrowUp/Down` volume ±5%, `?` Shortcuts Help modal) plus an on-demand full-screen immersive YRC lyrics stage (`收起` button or `Esc` closes, restores focus, and unmounts the fluid canvas; `>=1200px` `38% / 62%` layout with `− | 0.0s | +` lyric offset stepper).
  - Online-first paginated multi-channel search: `Ctrl+K` defaults to `'all'` (`全渠道聚合`, remembering `pruner_search_channel`), shows a max-5 `曲库中` local strip above `GET /api/search/multi` results, and navigates to `#view-search` (`100` results/page, `offset` `0..1000`, `has_more`, `加载更多`, relevance/quality sort).
  - Unified right-click context menu (`web/js/context_menu.js` in `#context-menu-host`) across catalog, discover, queue, and search rows (`播放`, `下一首播放`, `加入歌单`, `喜欢·取消喜欢`, `不再推荐` in `discover`, `查看相似`, `复制歌名-歌手`, viewport-clamped, keyboard-accessible).
  - Toast hygiene (`toast.js`): max 3 visible toasts (evicting oldest), 2-second dedupe, and `toast.quiet()` (1.2s, max 1 stacked) for frequent playback/volume adjustments.
- **Theme engine & controlled dynamic visual contract**:
  - Follow [DESIGN.md](DESIGN.md). Never reintroduce emoji-led labels, glassmorphism, generic blue SaaS styling, or English top-level navigation tabs.
  - Multi-theme appearance engine (`web/js/theme.js`): `dark` / `midnight` / `light` / `auto` via `html[data-theme]`, 6 accent presets + custom hex + `cover` mode (`--accent`, `--accent-subtle`, `--accent-contrast`), `comfortable` / `compact` density (`html[data-density]`), and `90% | 100% | 110% | 125%` font scale (`--font-scale`), synchronously applied from `localStorage` (`pruner_appearance`) at import to eliminate FOUC and synced with backend `settings.appearance`. Light theme meets WCAG >=4.5:1 contrast; semantic Keep `#62a368` and Prune `#df584c` remain immutable across all themes and accents.
  - Extract 4 quadrant dominant colors (`c1..c4`) from a `64×64` same-origin cover (`/api/cover`) to drive `--cover-accent`, `--cover-accent-subtle`, and the immersive stage fluid canvas.
  - Mount a single `256×256` 2D Canvas fluid oil-paint mesh gradient solely inside the immersive stage (24fps blend, 600ms color lerp, subtle 3% noise layer), cancelling `requestAnimationFrame` and unmounting on close, and pausing on blur, hidden tab, paused playback, `prefers-reduced-motion`, or `静谧省电` mode; offer two visual modes (`柔和动态` / `静谧省电`).
  - Use zero-reflow fixed-height YRC/LRC lyrics (distance-graded opacity, optional `lyrics_blur_depth`, `>5s` 3-dot HTML/CSS interlude indicator, per-song lyric offset stepper, zero-Cookie `amll-ttml-db` fallback, plus transparent desktop karaoke word-by-word sweep in `web/desktop_lyrics.html` with hover controls and style popover), discrete `?param=96/192/384` cover sizing, and crisp `1.5px` stroke SVG icons.
- **Multi-channel audio hub, ghost-audio invariants & best-quality arbitration contract**:
  - Support VIP/SVIP highest compatible quality ladder (`jymaster -> hires -> lossless -> exhigh -> standard`; `sky` marked experimental) via pure-Python EAPI signing, showing only honest backend-verified format, bitrate, and sample-rate badges.
  - Multi-channel provider hub covering `网易云`, `酷狗概念版` (`kugou_lite`), `咪咕音乐` (`migu`), `QQ音乐` (`qq`), `酷我` (`kuwo`), `B站` (`bilibili`), `GDStudio` (`gdstudio`), and `自定义` (`custom`), plus user NetEase Cloud Disk and Local Lossless Folder scanner. Search uses a dedicated paginated `search_page()` path on external providers (without strict audio-resolution `TrackQuery` dropping), shared module-level `_SEARCH_EXECUTOR` (`max_workers=8`), and `±3s` title+primary-artist dedupe merging `available_channels`.
  - **Best-Quality Cross-Channel Arbitrator** (`quality_arbitration`: `best_quality_race` default vs `netease_first`): returns immediately with zero extra latency when NetEase original is already verified lossless/Hi-Res/master full track; when unavailable/trial (or lossy `<500kbps` under `best_quality_race`), concurrently races Cloud Disk + Local Lossless + enabled channels and selects the strictly matching verified highest-quality full track via `score_audio_quality` (recording `quality_upgraded_from`).
  - **Strict per-channel credential isolation & SSRF boundary**: `ChannelCredentialVault` (`channel_credentials.json`) encrypts secrets at rest via Windows DPAPI and validates every channel `api_base` with `validate_custom_external_api`; `public_summary()` NEVER exposes raw secrets (`cookie`/`token`/`sessdata`/`dfid`). Each provider receives ONLY its own secret and sends it ONLY to its own trusted HTTPS host or validated `api_base` (stripping credentials across redirects). NetEase cookies NEVER touch external channels; `gdstudio` receives zero credentials; `custom` receives zero NetEase credentials.
  - **Bounded LRU `AudioDiskCache`** (`data_dir/audio_cache/`, default `512 MiB`, `0..4096`, `0` disables): atomically caches only verified `200` audio MIME streams in `/api/stream/{token}` under the configured cap (never caching HTML/errors).
  - **P0 ghost-audio & safe Web Audio invariants**: `player.js` MUST reset media elements solely via `resetMediaElement(el)` (`pause()` + `removeAttribute('src')` + `load()`, NEVER `.src = ''`), guard error events against `activeSrc` and `isLoadingTrack`, serialize `handleAudioElementError` as single-flight with `requestSequence`, and enforce a `timeupdate` dual-playback suppression guard so at most one `<audio>` element ever plays. `MediaElementAudioSourceNode -> DynamicsCompressorNode -> GainNode -> AnalyserNode` attaches ONLY to same-origin `/api/stream/{token}` URLs so direct cross-origin URLs never mute.
  - **SSE resilience**: `cloud.js` reconnects `/api/events` with bounded exponential backoff (`[1000, 2000, 5000, 15000]` ms) and cleanly cancels reconnect timers on `disconnectEvents()` / `auth:logout`.
- **Recommendations, shuffle & listening history contract**:
  - Martin Fiedler Balanced Dithered Shuffle (`shuffle_engine.py`) with play recency cooldown (`<7d` downweighted, `>30d`/unplayed boosted), artist/album dithering, adjacent artist-spread, and `playHistoryStack` for exact back-traversal (`POST /api/queue/smart-shuffle`).
  - Local `play_history` SQLite table records genuine listens (`>=30s` client / `>=25s` backend guard or `completed=True`, strictly excluding `歌单清理` quick prunes), powering 4-way local-first Smart Radio (`真·心动电台`: Dusty Gems + Fresh Rotation + Multi-Seed `/simi/song` graph intersection + FM/Daily exploration), `沉睡宝藏`, and `本地听歌洞察`, alongside 4 native read-only feeds (`每日推荐`, `私人漫游`, `心动模式`, `相似歌曲`) with explicit-feedback-only reranking.
- **Safety & persistence invariants**:
  - Account-partitioned `SQLite WAL` storage (`catalog.sqlite3`, including `play_history`, `explicit_feedback`, `local_files`) with staged single-transaction sync replacement and zero cross-account leakage.
  - Encrypt persisted NetEase session cookies (`SessionStore`) and per-channel credentials (`ChannelCredentialVault`) at rest on Windows via DPAPI (`CryptProtectData`/`CryptUnprotectData` with `CRYPTPROTECT_UI_FORBIDDEN`), preserving fail-closed/quarantine handling on corrupt data.
  - Enforce trusted HTTPS upstream allowlists (`music.163.com`, `interface.music.163.com`, `interface3.music.163.com`), strip `Cookie` headers on cross-host redirects, restrict `/api/cover` to `*.126.net` / `*.music.126.net` HTTPS without cookies, and parse `amll-ttml-db` XML with DTD/XXE disabled.
  - Deck preview playback uses `{ preserveQueue: true, origin: 'deck' }` (stopping cleanly on track end without clobbering or advancing the global listening queue) and shows cached static lyrics for the active Deck card (`未在播放 · 按 P 试听`) whenever the global player is on another song.
  - Single-track destructive actions default to visible instant mode with a 3-second local soft-commit window (`立即同步 3s | 批量确认` segmented toggle; `Z` cancels the newest uncommitted action; closing the app cancels soft commits; batch mode persists and always requires grouped confirmation).
  - In the liked playlist, destructive action means unlike; in a self-created (`self_created`) playlist, it means remove from that playlist. Subscribed playlists and local `imported` sources are never remotely writable. Bulk and rule-derived actions never bypass grouped confirmation.
  - Freeze destructive confirmation manifests (including `session_generation` and `manifest_hash`) at confirmation time; verify active `session_generation` before executing.
  - Unknown remote writes freeze destructive operations and never resolve prematurely on transient or truncated reads (requiring complete, fresh snapshot verification or explicit user ignore with durable tombstones); never blind-retry or drop unconfirmed IDs locally.
  - `L` marks persistent relisten-later (`稍后再听`); deck shortcuts are scoped to `歌单清理` and strictly ignore `e.repeat` and IME composition (`e.isComposing`).
- **Distribution**: Cross-platform Python/Web source; Windows ships as a clean GUI one-file executable (`console=False`, version `0.3.0`, branded with `web/assets/icon.ico`, bundling `web/` including `web/desktop_lyrics.html` plus `webview`/`pythonnet`/`clr_loader` DLLs via `collect_all`, with Start Menu registration script and CLI/headless env overrides preserved). ## Ownership

- Backend core worker: `pyproject.toml`, `version.py`, core config/models/storage (`SessionStore`, `SettingsStore`, `ChannelCredentialVault`, `AudioDiskCache`), SQLite DB (`db.py`), catalog/journal/operations, Starlette `app.py`, desktop shell/transparent floating lyrics/global hotkeys (`desktop.py`), entry points, `tests/backend/test_backend.py`.
- NetEase protocol & audio worker: `netease_crypto.py`, `netease_client.py`, `external_sources.py`, `audio_service.py`, `recommend_service.py`, `shuffle_engine.py`, `amll_lyrics.py`, `tests/backend/test_audio_and_protocol.py`.
- Frontend core & experience workers: `web/**` (including `web/desktop_lyrics.html`, `web/js/theme.js`, `web/js/search_view.js`, `web/js/context_menu.js`, `web/css/search.css`), `tests/frontend/**`.
- Docs & packaging / integration owner: root docs (`AGENTS.md`, `DESIGN.md`, `ACCEPTANCE.md`, `README.md`), packaging spec (`Pruner-Studio.spec`), `requirements-build.lock`, Windows build & shortcut scripts (`scripts/build-windows.ps1`, `scripts/install-start-menu.ps1`), CI, and final cross-scope fixes.

Workers must not edit paths outside their ownership, initialize or modify Git history, install global software, access the parent directory's private data, call live NetEase write endpoints, or publish anything.

## Release Automation Convention

- After finishing a verified optimization pass when the user requests auto-upgrade and push, use `scripts/upgrade-and-push.ps1` (stops running `Pruner-Studio.exe`, rebuilds `dist/Pruner-Studio.exe` in-place via `scripts/build-windows.ps1`, runs `scripts/verify-windows.py`, refreshes the Start Menu shortcut, and stages/commits/pushes clean changes to GitHub `origin/main`).

## API contract

All JSON responses use an actual HTTP status and this shape:

```json
{"ok": true, "data": {}, "error": null}
```

Failures use:

```json
{"ok": false, "data": null, "error": {"code": "STABLE_CODE", "message": "User-facing message"}}
```

Core routes are documented in [ARCHITECTURE.md](ARCHITECTURE.md); the `0.3.0` desktop client extends the loopback API with:

- Audio, streaming & cache: `GET /api/audio` (supports `quality`, `allow_external`, `force_refresh`, and direct cross-channel `provider`/`external_id`/`title`/`artist`/`duration`/`stream_url_hint`), `GET /api/audio/candidates`, `GET /api/stream/{token}` (HTTP Range `200/206/416`, verified audio cache-through, strict credential isolation), `GET /api/lyrics` (`yrc`, `romalrc`, `chorus_start`, `chorus_end`, optional `amll-ttml-db` fallback with `ttml_source`), `GET /api/cache/audio/stats`, `DELETE /api/cache/audio`.
- Multi-channel hub & paginated search: `GET /api/channels`, `PUT /api/channels/{channel_id}` (`clear_credentials: true`), `POST /api/channels/{channel_id}/test`, `GET /api/search`, `GET /api/search/multi` (`q`, `channels`, `limit` `1..100`, `offset` `0..1000`, returns `has_more`, `tracks`, `channel_errors`).
- Discovery, queue, history & library writes: `GET /api/cloud`, `GET /api/recommend/daily`, `GET /api/recommend/fm`, `GET /api/recommend/intelligence`, `GET /api/recommend/similar`, `GET /api/recommend/smart-radio` (`explore_ratio` `0.1..0.8`, `exclude_ids`, `limit`), `GET /api/recommend/dusty-gems` (`limit`), `GET /api/insights`, `POST /api/playback/record`, `POST /api/queue/smart-shuffle`, `POST /api/feedback`, `DELETE /api/feedback`, `POST /api/operations/like`, `POST /api/playlists/{id}/add-tracks`.
- Settings, local audio, cover & desktop/SSE bridge: `GET /api/settings`, `PUT /api/settings` (including `appearance`, `desktop_lyrics_style`, `desktop_lyrics_bounds`), `POST /api/local-library/scan`, `GET /api/cover` (`*.126.net` HTTPS allowlist, discrete `{64,96,192,384}` sizes, no cookies), `POST /api/desktop/lyrics-window`, `POST /api/desktop/playback-state`, `POST /api/desktop/command` (allowlisted `next|prev|toggle_play|toggle_like`), `GET /api/events` (SSE `sync`, `desktop_lyrics`, `desktop_lyrics_style`, and `hotkey` events with replay on connect).
